# Бэкап-система с ротацией архивов

> Bash-скрипт + cron, который каждую ночь архивирует выбранную папку и хранит только последние 7 архивов — старые удаляются автоматически.

## Описание проекта

Простая и надёжная система резервного копирования для одного сервера: без внешних зависимостей, без сложных агентов — только `tar`, `cron` и ротация по количеству хранимых копий. Подходит как базовый уровень защиты данных (конфигов, веб-каталогов, баз в виде дампов и т.д.) до внедрения более комплексного решения (restic/borg и т.п.).

## Стек

- Bash
- `tar` + `gzip`
- cron
- `find` (для автоматической очистки старых архивов)

## Структура репозитория

```
backup-system/
├── README.md
├── backup.sh              # основной скрипт создания и ротации архивов
├── crontab.example        # пример записи в crontab для ночного запуска
└── backups/
    └── .gitkeep           # папка-пример для хранения архивов
```

## Логика работы скрипта

1. Архивирует указанную директорию (`SOURCE_DIR`) в `.tar.gz` с именем, включающим дату и время создания.
2. Кладёт архив в директорию назначения (`BACKUP_DIR`).
3. Подсчитывает количество существующих архивов в `BACKUP_DIR`.
4. Если архивов больше 7 — удаляет самые старые, оставляя только последние 7.
5. Пишет в лог информацию о созданном архиве и об удалённых старых копиях.

## Установка и использование

### 1. Настроить пути в скрипте

Отредактировать переменные `SOURCE_DIR` и `BACKUP_DIR` в начале `backup.sh` под свои нужды.

### 2. Разместить скрипт на сервере

```bash
sudo mkdir -p /opt/backup-system
sudo cp backup.sh /opt/backup-system/backup.sh
sudo chmod +x /opt/backup-system/backup.sh
sudo mkdir -p /var/backups/my-data
```

### 3. Запустить вручную для проверки

```bash
sudo /opt/backup-system/backup.sh
ls -lh /var/backups/my-data
```

### 4. Добавить в cron (запуск каждую ночь в 02:00)

```bash
sudo crontab -e
```

```cron
0 2 * * * /opt/backup-system/backup.sh >> /var/log/backup-system.log 2>&1
```

### 5. Проверка ротации

После накопления более 7 архивов (можно сэмулировать, запустив скрипт вручную несколько раз подряд) — убедиться, что в `BACKUP_DIR` остаётся ровно 7 последних файлов:

```bash
ls -1 /var/backups/my-data | wc -l   # должно быть 7
```

## Пример вывода в лог

```
[2026-10-15 02:00:01] Создан архив: my-data_2026-10-15_02-00-01.tar.gz (размер 128M)
[2026-10-15 02:00:02] Найдено архивов: 9. Хранить нужно: 7. Удаляю 2 старых.
[2026-10-15 02:00:02] Удалён старый архив: my-data_2026-10-08_02-00-01.tar.gz
[2026-10-15 02:00:02] Удалён старый архив: my-data_2026-10-09_02-00-01.tar.gz
```

## Возможные доработки

- Копирование архивов на удалённое хранилище (S3/другой сервер) после создания.
- Шифрование архивов (gpg) перед хранением.
- Уведомление в Telegram/почту при ошибке создания бэкапа.
